## 毎日のブリーフィング
- 送る時間帯は10時〜18時（api/morning-brief.ts の BRIEF_HOUR / BRIEF_UNTIL）。その日の最初の実行で送る。
- 呼ぶ側は3つ。どれが先に走っても、その日1回しか送らない（brief_sent で二重送信を防ぐ。送れたときだけ記録する）。
  1. Vercel Cron（vercel.json: 毎日 01:00 UTC = 10:00 JST。Hobbyは±1時間のずれあり）
  2. GitHub Actions の定時実行（Assistant Scheduler）。時刻通りには走らない。朝に走らない日が多い（実測）
  3. LINEの手動コマンド「ブリーフィング」（自分だけ）／「ブリーフィング全員」（管理者のみ）
- 届く人: 未完了のメモ・予定がある人、または日報の約束が期日になった人。管理者(八木・桝田)は未完了メモがあるとき全体版。
- LINEの「プッシュ送信」には月の上限がある。上限に達すると 429 で届かない（2026-09/30に実際に発生）。現在はライトプラン。

## 届かなかったとき、まず見る場所
1. Stella → 管理者 → 「配信記録」: 日ごとの状況、実行の記録（経路・時間帯・送った人・送らなかった理由）、Vercel Cronが認証で断られた日

## 過去の障害と原因（同じ失敗をしない）
- **tsconfig.json を置かない**: 置くと Vercel が ES module で出力し、LINEの受信関数が起動できなくなった（約1日止まった）。型チェックのCIはコマンドラインの指定で動かしている。
- **構文エラー**: 置換のミスで行頭に余計な文字が残り、関数全体が動かなくなった。型チェックCI（.github/workflows/typecheck.yml）は構文エラー(TS1xxx)だけを失敗にする。
- **Vercel Cron が毎日認証で断られていた**: サーバーに CRON_SECRET が無かった（配信記録の「認証で断った呼び出し」で判明）。現在は、CRON_SECRET が無い間は user-agent が vercel-cron の呼び出しを受け付ける。CRON_SECRET を設定すると、自動でBearer認証に切り替わる（force / only は常にトークン付きのみ）。
- **GitHubの定時実行は当てにならない**: 過去6日のうち5日、10〜13時に走らなかった。時間帯を18時まで広げた。
- **日報の保存先は work_reports**。既存の daily に入れない（飲食の日報が混ざって管理画面が白くなった）。

## 変更するときの手順（必須）
1. 編集の前に、最新のファイルと直近のコミットを読み直す（他の人の変更が入っていることがある）。
2. 置換は「一致が1か所のときだけ」。括弧の数を確認する。
3. コミット後は、GitHubの中身・型チェックCI・Vercelの反映を確認する。
4. **「Ready」は動いている証拠ではない。** LINEで実際に送る／配信記録を見る、など、動いた記録を確認するまで「完了」としない。
5. 営業時間中の本番変更は避ける。入店・件数の処理に触るときは特に。
